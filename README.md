# LDT MISIS LOLIPOP — мониторинг и предиктивная аналитика (ЛЦТ 2026, ДЖКХ)

Текущая локальная ветка: `release/final-rc`, исходная база `main@5d64126`.
Свежая проверка и ограничения: [приёмка 16.10.2026](docs/FINAL_ACCEPTANCE_2026-10.md).
Первые 11 коммитов до `a5ba6e0` ранее опубликованы в старой ветке; новые RC-коммиты локальные. RC на публичном стенде не развёрнут.

Веб-сервис диспетчера ОДС для инженерных коллекторов Москвы: карта, объекты, датчики, история наблюдений, фактические тревоги, журнал событий, профилактические заявки, импорт, уведомления и журнал прогнозов с решениями диспетчера.

**Прогноз.** Подключён ML-пакет LCT_ML_backend_v1.1. Газовая модель оценивает наблюдаемое пересечение газом 1 % CH4 в сутки D+2 (shadow; горизонт отсчитывается от завершения суток данных). Это **не вероятность пожара** и не подтверждённый инцидент. Модуль инцидентов со stub-метками отключён и не запускается. Реальные прогнозы других классов требуют доработки ML. Подробнее: [docs/ML_INTEGRATION_RU.md](docs/ML_INTEGRATION_RU.md).

При локальном запуске пользователи создаются отдельно по инструкции ниже. На Railway сейчас нет постоянного scheduler/integration worker; это ограничение опубликованного демо.

## Запуск

1. Скопировать backend/.env.example в backend/.env, заменить пароль БД.
2. Из корня: `docker compose --env-file backend/.env -f infra/compose.yaml up --build -d`.
3. Создать администратора: `docker compose --env-file backend/.env -f infra/compose.yaml exec backend python -m app.admin create-user admin --role admin`.
4. Открыть http://localhost:8080 и войти. Внешний вид (тёмная, бежевая или как на устройстве) выбирается в «Настройках».

Нет встроенных пользователей/паролей. Для работы загрузить обезличенные справочники объектов и каналов, затем события.
Миграции применяются автоматически контейнером migrate. Не используйте create_all для обновления существующей БД.

Роли: `manager` — просмотр, `technician` — обычные заявки, `dispatcher` — диспетчерские действия, `analyst` — решения по прогнозам, `admin` — администрирование, `integrator` — машинный обмен. Полная матрица — [SECURITY](docs/SECURITY.md).
Из рекомендации создаётся **черновик**: диспетчер проверяет тему, описание и приоритет, затем подтверждает. Статусы: `draft → new → in_progress → completed / cancelled`.
Ручная профилактическая заявка сохраняет прежний стартовый статус `new`.

## Прогноз (ML)

Расчёт идёт раз в сутки отдельной задачей, API модель не запускает и читает готовый результат из БД.

1. Проверить, что в `models/bundles/` находятся `gas_cross_v3_bundle.zip`, его `.sha256` и `ACTIVE.json`. Утверждённый газовый бандл включён в репозиторий; его SHA-256 проверяется при запуске.
2. Окружение задачи: Python 3.12, `pip install -r backend/requirements-ml.txt`.
3. Запуск: `cd backend && python -m scripts.run_ml_daily --ready-marker /data/ready_YYYY-MM-DD.txt --date YYYY-MM-DD`. Маркер содержит дату завершённых суток. Нужна история журнала не меньше 401 суток вместе с D. Для планировщика используйте профиль Docker `ml`; подробности и внешние CSV — в инструкции ML.

Без бандлов и без запуска задачи приложение работает, журнал прогнозов пуст (`/predictions/status` → `no_ml_run_yet`).
