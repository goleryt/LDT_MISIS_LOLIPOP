# ЛЦТ 2026 — сервис прогнозирования аварий

Веб-сервис для диспетчеров АО «Москоллектор». Система объединяет журнал событий датчиков, мониторинг объектов, активные тревоги, историю каналов и профилактические заявки. ML-модуль подключается отдельно и в текущей ветке не подменяется фиктивными прогнозами.

## Реализовано

- авторская интерактивная SVG-схема Москвы без внешней картографической подложки;
- статусы объектов: `normal`, `alarm`, `unknown`;
- карточка объекта и список связанных датчиков;
- карточка датчика с последним значением и историей;
- линейный график для числовых каналов и timeline для состояний;
- активные тревоги с переходом к конкретному объекту/каналу;
- журнал событий с фильтрацией и пагинацией;
- список объектов с поиском и фильтрами;
- идемпотентный импорт CSV журнала событий;
- реестр импортов;
- профилактические заявки по объекту или конкретному датчику;
- PostgreSQL + Alembic.

## Структура

- `backend/` — FastAPI, SQLAlchemy, импорт данных и REST API;
- `frontend/` — React + TypeScript + Vite;
- `infra/` — локальная инфраструктура PostgreSQL;
- `ml/` — зона ответственности ML-части команды;
- `data/README.md` — правила работы с исходными данными;
- `docs/` — архитектурные и эксплуатационные заметки.

Дизайн и ограничения карты: [`docs/MAP_DESIGN_RU.md`](docs/MAP_DESIGN_RU.md),
проверка покрытия ТЗ: [`docs/MAP_TZ_COVERAGE_RU.md`](docs/MAP_TZ_COVERAGE_RU.md).

## Локальный запуск

### 1. PostgreSQL

Создайте `backend/.env` из `backend/.env.example`, затем из корня проекта:

```powershell
cd infra
docker compose up -d
```

По умолчанию контейнер PostgreSQL доступен на `localhost:5433`.

### 2. Backend

```powershell
cd backend
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Swagger: `http://127.0.0.1:8000/docs`.

### 3. Frontend

При необходимости создайте `frontend/.env` из `frontend/.env.example`.

```powershell
cd frontend
npm.cmd install
npm.cmd run dev
```

Frontend по умолчанию: `http://localhost:5173`.

## Важные оговорки демонстрации

Реальные координаты объектов в исходном наборе не предоставлены. Точки объектов детерминированно вычисляются из `object_id` и не означают реальные адреса или зоны риска; это явно отмечено в интерфейсе. Каналы связываются с объектами через `channel_catalogue.ид_объект`, а события — через `ид_канала_данных`; эта связь не определяет физический тип объекта или количество устройств. При загрузке поставленных файлов синтетично размещение точек, а не записи каналов и событий. Авторская SVG-схема даёт узнаваемый городской контекст, но не является точной картой. Отсутствие события у канала не трактуется как аппаратный отказ — такой канал получает статус `unknown`.

Для просмотра без PostgreSQL есть отдельный сервер с полностью вымышленными
объектами, каналами, событиями и координатами. Из каталога `backend` запустите
`python -m scripts.demo_preview --port 8001`, затем задайте в
`frontend/.env.local` строку `VITE_API_BASE_URL=http://127.0.0.1:8001` и
запустите frontend. Интерфейс отмечает такой режим «Демо-данные»;
профилактические заявки в нём недоступны. Этот сервер предназначен только для
проверки интерфейса, а не ML-метрик или соответствия физической карте.

## ML-интеграция

Frontend и backend не генерируют фиктивный `risk_score`. После согласования контракта модели сортировка датчиков должна быть:

1. активная тревога;
2. ML-риск по убыванию;
3. время последней информации по убыванию;
4. `channel_id` как стабильный tie-breaker.

## Перед production

Для промышленного внедрения остаются отдельные инфраструктурные задачи: LDAP/AD, RBAC, аудит действий, TLS 1.2+, резервное копирование/восстановление, нагрузочное тестирование, получение достоверных геоданных и production-развёртывание Linux.
