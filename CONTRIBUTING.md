# Правила работы с репозиторием

## Ветки

В `main` напрямую не коммитим. Для каждой задачи используем отдельную ветку:

- `feature/<область>-<задача>` — новая функциональность;
- `fix/<область>-<проблема>` — исправление;
- `docs/<задача>` — документация;
- `chore/<задача>` — инфраструктура и обслуживание.

Примеры: `feature/backend-events`, `feature/frontend-requests`, `fix/map-click`.

## Перед началом работы

```bash
git switch main
git pull --ff-only origin main
git switch -c feature/my-task
```

Если команда работает в общей рабочей ветке хакатона, сначала синхронизируйтесь с тимлидом, чтобы не потерять параллельные изменения.

## Перед Pull Request

- проверить, что `.env`, ключи и токены не попали в Git;
- не добавлять исходные датасеты и обученные модели;
- выполнить backend smoke-check / миграции при изменении БД;
- выполнить `npm.cmd run build` для frontend;
- обновить README или `docs/PROJECT_STATUS.md`, если изменился пользовательский сценарий.

## Кодировки

Исходники хранятся в UTF-8. Для новых файлов в Visual Studio 2022 при необходимости используйте «Сохранить с кодировкой… → UTF-8 (65001)».
