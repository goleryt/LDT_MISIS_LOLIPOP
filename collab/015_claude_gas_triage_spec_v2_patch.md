## 1. Конец суток и retro (014 п. 2)

- **Live.** Для события с c > D 23:59:59 вызов на конец суток D даёт `status = pending_at_day_end`.
  - Такое событие входит в суточную нагрузку и в очередь внимания **суток D**, по дате t₀.
  - Зрелая `triage_live` появляется при первом вызове с as_of_t ≥ c.
- **Retro** считается строго по данным ≤ D 23:59:59.
  - Если c > D 23:59:59, у события `triage_retro = censored_by_day` и метки нет.
  - Позднего пересчёта retro не делаем: retro — это «что было известно на конец суток D».
- **`censored_right`** — только для конца **архива**: c позже последнего момента данных. Для retro — если конец
  суток позже конца архива.
- **Синтетический тест.** t₀ = 31.12 23:55, спад 01.01 00:02, январские показания в данных есть.
  - На конец 31.12: `pending_at_day_end`, retro = `censored_by_day`.
  - При as_of = 01.01 00:10: live = зрелая метка.
  - Январские показания не влияют на retro 31.12.

## 2. Отсутствие показаний после спада (014 п. 3)

Утверждение «журнал фиксирует изменения значений» **снимаю**: подтверждённого контракта change-only для газового
потока у нас нет. Вместо него — явное ограничение и диагностика.

- **`state_at_c`** — состояние канала в момент c по наблюдениям:
  - `observed_below` — есть газовое показание в [c − 10 мин; c], все значения < 1 %, и нет повтора ≥ 1 % после
    `drop_t`;
  - `inferred_below` — последнее показание до c < 1 % (спад наблюдён, повтора нет), но оно старше 10 мин на момент c;
  - `unknown` — спад не наблюдён: это уже `needs_attention` / `unresolved_or_incomplete`.
- **Основное правило.** `likely_after_maintenance` и `likely_bump_test` допускаются при `observed_below` **или**
  `inferred_below`. Метка всегда несёт поле `state_at_c`, в интерфейсе показывается «состояние после спада выведено,
  не наблюдено».
- **Строгий вариант** (чувствительность, без выбора): `likely_*` только при `observed_below`, остальное — в очередь
  внимания. V1 и N1 считаются для обоих вариантов, решение по stop-rule принимается по основному. Порог 10 мин
  фиксирован **до** FULL.
- **Диагностика в 21:** распределение давности последнего газового показания перед c (≤ 1, 1–5, 5–10, 10–30,
  30–120, > 120 мин) у кандидатов `likely_*`; доли `observed_below` / `inferred_below` по периодам. На SMOKE сначала
  проверяем покрытие.
- **Формулировка безопасности** вместо «идущее событие всегда needs_attention»: событие без наблюдённого спада или с
  наблюдённым повтором ≥ 1 % до c — всегда `needs_attention`. При ненаблюдаемом состоянии в c метка выводится и
  помечается `inferred_below`.
  - Дополнительная защита: любое новое строгое пересечение 1 % на канале после c — **новая тревога** со своим
    триажем. Ошибка метки не распространяется на последующий рост газа.

## 3. Тишина и N1 (014 п. 4)

- **(a) Подтверждаю.** `after_silence = true` только при фактически наблюдённых **обеих** границах тишины: показания
  объекта до начала и после конца.
  - Нет левой границы (история начинается с тишины или короче 90 суток) → `unknown`, не `false`.
  - 90 суток — необходимое условие, а не достаточное.
- **(b) N1, края и знаменатель:**
  - сдвиг k ∈ {−2, −1, +1, +2} недель выбирается на канал, seed 21, 20 перестановок;
  - если сдвинутое событие выходит за [начало архива; конец архива − 1 сут], для этого канала берётся −k: отражение;
  - если и так выходит, событие остаётся на месте и считается в `n1_unshifted` (выводится);
  - знаменатель один и тот же: **все** события периода, период — по **исходной** дате t₀, для реальной и для
    переставленных долей.
  - Форма события (`ended_fast`, `peak_by_c`, `state_at_c`) едет вместе с событием: она определяется своим каналом.
    **Контекст тишины после сдвига не используется.**
  - Сравнивается метка «только серия»: `series_only = форма ОК ∧ other_ch_by_live_cutoff ≥ 1`, без
    `after_silence`. Одинаково для реальных и переставленных событий.
  - N1 проходит, если реальная доля `series_only` больше максимума из 20 перестановок, в объединённых периодах
    ≤ 2024 и 2025.
