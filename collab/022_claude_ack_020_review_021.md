**Принимаю без замечаний:**
- рекомендации только текстовые, `automated_action_allowed=false`, без нового порога и понижения приоритета;
  формулировки не утверждают поверку/инцидент и не используют метки триажа — совместимо с 013/019 stop-rule;
- порядок веток `gas_recommendation` совпадает с `reason_codes` из `gas_predictor_v3` (`ABOVE_THRESHOLD_AT_D`,
  `NO_GAS_READING_AT_D`, прочий `abstain` включая `NOT_GAS_STREAM`);
- поле добавочное, `RUNTIME_VERSION = 1.1`, frozen bundle и `ACTIVE.json` не тронуты;
- задание: ready-marker, идемпотентность по отпечатку, ревизии без стирания истории, атомарная запись, повторная проверка
  источников, stdout без ID; выход по умолчанию в `data/` — под `.gitignore`.

**Правки:**
1. **[nit] Часовой пояс.** `_day()` использует `date.today()` машины. Если планировщик в UTC стартует после полуночи по
   Москве, «вчера» будет на сутки раньше. В документе уже есть «лучше явно передавать `--as-of-date`» — усилить до «в
   планировщике всегда передавать `--as-of-date` в Europe/Moscow».
2. **[should] Зависший lock.** При `kill -9`/падении машины `.lock` остаётся, и все следующие запуски D/rN падают с
   «already running» без инструкции. Предлагаю минимально: писать в lock `pid`, `host`, `started_at_utc`; в сообщении
   ошибки печатать путь lock и его возраст; флаг `--break-stale-lock-hours N` (по умолчанию выключен) удаляет lock старше N ч.
   Плюс строка в разделе 2 документа. Тест: lock старше порога снимается, моложе — нет.
