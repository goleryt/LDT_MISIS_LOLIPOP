# Протокол совместной работы Claude ↔ Codex (ветка `ml-models`)

Действует с 2026-09-25 по решению Даши. Заменяет обмен через Google Drive (документы 00–52).

## Роли

| кто | роль |
|---|---|
| **Claude** | «Мозг»: постановка задач, дизайн экспериментов, предрегистрация, ревью кода, интерпретация результатов. |
| **Codex** | Исполнитель и devil's advocate. До кода оспаривает спецификацию: ищет утечки, ошибки цели, слабые места оценки. После согласования реализует, пишет тесты, генерирует ноутбуки. |
| **Даша** | Владелец решений: данные и заморозка, что уходит backend'у, необратимые шаги. Запускает ноутбуки на Kaggle и передаёт результаты. |

Код пишется без одобрения Даши, как только Claude и Codex оба согласовали спецификацию.

## Цикл одной задачи

1. **Спецификация.** Claude пишет `collab/NNN_claude_<тема>_spec.md`.
2. **Возражения.** Codex отвечает файлом `collab/NNN_codex_<тема>_objections.md`: что неверно, чего не хватает, что проще. Итераций столько, сколько нужно.
3. **Согласование.** Оба пишут строку `AGREED: <тема> @ <commit>` в `collab/STATE.md`. До этого кода нет.
4. **Реализация.** Codex работает в ветке `codex/<тема>`, открывает PR в `ml-models`, `pytest tests -q` зелёный.
5. **Ревью.** Claude пишет `collab/NNN_claude_<тема>_review.md` с замечаниями по файлам и строкам. У Claude в этой среде нет GitHub API: он читает ветки через git, а комментарии оставляет файлами, не в PR. Codex исправляет.
6. **Мерж.** Оба пишут `APPROVED: <тема> @ <commit>` в `STATE.md`, Codex мержит.
7. **Прогон.** Даша запускает ноутбук на Kaggle и передаёт zip с результатами Claude в чат.
8. **Решение.** Claude кладёт агрегатную сводку в `collab/results/` и пишет файл с решением по заранее заданным порогам.

Claude проверяет ветку только когда Даша пишет «resume», без опроса по расписанию.

## Формат сообщения

Файлы `collab/NNN_<автор>_<тема>_<вид>.md`. NNN — сквозной трёхзначный номер: следующий свободный.

```
# NNN · <автор> · <тема> · <вид: spec | objections | review | results | decision>
Статус: draft | needs-reply | agreed | blocked
Ход: claude | codex | даша
Нужно решение Даши: нет | <что именно>
Ссылки: <предыдущие файлы, коммиты, ветки>
---
<текст: коротко, пронумерованными пунктами; факт / измерение / вывод помечать явно>
```

`collab/STATE.md` — одна страница состояния. Каждый обновляет её в конце своего хода: активные темы, чей ход, что
согласовано, открытые вопросы к Даше.

## Жёсткие правила

1. **Нет данных в репозитории.** Сырых данных, идентификаторов каналов и объектов, секретов, моделей и `.env` в репо нет. Только код,
   тесты на синтетике, сгенерированные ноутбуки и агрегаты.
2. **Ноутбуки не правятся руками.** Они генерируются скриптами `ml/sensor_failure/generate_*.py`, тест проверяет, что сгенерированный ноутбук
   компилируется и встраивает текущий код.
3. **`pytest tests -q` зелёный** в каждом PR. Версии для Kaggle и backend: Python 3.11–3.12, numpy 2.0.2,
   pandas 2.3.3, polars 1.35.2, lightgbm 4.6.0, sklearn 1.6.1.
4. **Предрегистрация.** Цели, признаки, список моделей, метрики и пороги фиксируются в spec до прогона. После
   просмотра подтверждающих результатов ничего не подбирается. Число опробованных вариантов записывается.
5. **Честность выводов.** Proxy не называется подтверждённым инцидентом. 2025 H2 и 2026 H1 проектом уже
   просматривались — это development-проверки, не независимый тест.
6. **Замороженные артефакты** (уже у backend) не меняются:
   - `gas_cross_v3_bundle.zip` — SHA `1747b09c0a289f8509b1ef066442936f315c4f7958d1815825a7f90296503e20`;
   - `incident_head_bundle.zip` — SHA `3c8b4b46ae8b17f12a5e6aa16e3722a9907817c65c73cbed3a06880203d1e2c5`;
   - интерфейс `ml/sensor_failure/lct_ml_runtime.py`: `MLRuntime(bundles_dir).score_day(...)`. Изменения только
     добавляющие, с тестом обратной совместимости.
7. **Совместимость новых моделей.** Новый газовый bundle — drop-in:
   - тот же API predictor: `load_bundle`, `build_features`, `predict`;
   - те же поля выхода, новые только добавляются;
   - все новые признаки считаются внутри `build_features` из журнала и справочника;
   - загружается `lct_ml_runtime` (тест вида `test_runtime_is_drop_in_for_a_second_gas_bundle`);
   - ZIP + `.sha256`, без pickle.
8. **Только Даша решает:**
   - снятие заморозки данных;
   - что уходит backend'у;
   - замена активной модели (`ACTIVE.json`);
   - любые необратимые действия.
