# Границы финальной доработки — 16.10.2026

Источник решений — прямое указание владельца проекта после консультации с жюри.
Ожидание новых ответов не блокирует работу. Это решения этапа, а не приписанные жюри требования.

- Замороженный газовый runtime сохраняется без изменения математики. Новые модели, классы, сезонность и retraining не входят в этап.
- Shadow/proxy оценка наблюдаемого пересечения порога не подтверждает вероятность физического инцидента. Inference на синтетических входах проверяет интеграцию, не качество модели.
- Фактическая тревога, прогноз, рекомендация, черновик и заявка — разные сущности. Нет автоматических критических уведомлений по shadow-результатам.
- Point в GeoJSON/WKT достаточно. Условные точки маркируются, реальные координаты не выдумываются. Линии и полигоны не добавляются.
- Пять mock-источников проверяют adapter layer: СМВУ/telemetry, ОДС, оборудование, статусы заявок, погода. Промышленное подключение требует данных заказчика.
- Внутренние web-уведомления: хранение, индивидуальное прочтение, переход, дедупликация, polling. SMTP/SMS/Telegram и новая политика эскалации не добавляются.
- Существующие RBAC/LDAPS/audit сохраняются и проверяются. `manager` является ролью просмотра; новой роли `viewer` нет.
- Из рекомендации создаётся редактируемый `draft`. Подтверждение admin/dispatcher переводит его в `new`; далее `in_progress`, `completed` или `cancelled`. Терминальные статусы не открываются повторно.
- Analyst сохраняет право решения и создания черновика по существующей политике прогнозов; проверка/публикация черновика — admin/dispatcher. Technician работает с подтверждёнными заявками.
- Top-K/cooldown задаёт администратор окружения. UI-редактора рабочей политики нет. Изменять конфигурацию без переоценки качества не следует.
- Рекомендации runtime отображаются с происхождением и требуют ручной проверки. Новые предметные правила РТЭК не выдумываются.
- Нагрузочные измерения и backup/restore публикуются как измеренные результаты. Новых нормативов деградации, RPO/RTO не назначается. Проверка 200 тысяч событий не доказывает восстановление 12-летнего массива за 4 часа.

Неоднозначности разрешены консервативно: сохраняются рабочие сценарии, ограничения показываются явно, внешние данные не заменяются предположениями.
