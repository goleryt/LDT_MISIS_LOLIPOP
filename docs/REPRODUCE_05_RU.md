# Как воспроизвести notebook 05: `05_lightgbm_propensity_research_cpu.ipynb`

Исходник: `ml/sensor_failure/pre2025_audit_runtime.py` (разделы 1–8), `weather_runtime.py` и
`weather_data.py` (раздел 9, погода; план — `docs/EXPERIMENT_05W_WEATHER_RU.md`); ноутбук генерируется
`python ml/sensor_failure/generate_pre2025_audit_notebook.py`; тесты — `tests/test_pre2025_audit_runtime.py`, `tests/test_weather_runtime.py`.
После правки runtime обязательно регенерировать ноутбук: тест проверяет, что код встроен дословно.

## Что нужно

- Kaggle Notebook, **Settings → Accelerator → None** (только CPU).
- Приватный обезличенный Kaggle Dataset с панелью v2: `panel_manifest_v2.json` и Parquet-файл,
  указанный в нём (`data_file`). Тот же dataset, что у четырёх исходных notebook.
- Интернет не нужен. Если LightGBM вдруг нет в образе, notebook поставит `lightgbm>=4.4,<5`
  (для этого нужен интернет; в стандартном образе Kaggle LightGBM есть).

## Шаги

1. Импортировать notebook в Kaggle (**File → Import Notebook**).
2. **Add Input** → подключить приватный dataset панели. Путь вводить не нужно: notebook сам ищет
   ровно один `panel_manifest_v2.json` в `/kaggle/input`. Если найдено 0 или больше одного —
   прогон остановится с понятной ошибкой.
3. **Settings → Accelerator → None.**
4. В единственной редактируемой ячейке выбрать режим:
   - `MODE = "SMOKE"` — быстрая проверка, что всё работает: ~1/20 каналов (детерминированно),
     30 деревьев, 50 повторов бутстрэпа. Результаты помечены `non_comparable`, сравнивать их нельзя.
   - `MODE = "FULL"` — настоящий прогон: все каналы, 500 деревьев, 500 повторов бутстрэпа.
   - `RUN_MAIN` / `RUN_WEATHER` включают разделы 1–8 и раздел 9. Если основной FULL-прогон уже есть,
     можно поставить `RUN_MAIN = False` и получить только погоду.
5. **Run All** (для чистоты — **Restart & Run All**).

## Ожидаемые время и память

| режим | время | пик RAM |
| --- | --- | --- |
| SMOKE | 1–3 мин | 2–3 ГБ |
| FULL, разделы 1–8 | ≈9 мин (факт 2026-09-23: 511 с на 4 CPU) | 6–10 ГБ |
| FULL, раздел 9 (погода) | ≈4–6 мин (оценка) | 6–10 ГБ |

Стандартного Kaggle CPU-ноутбука (4 ядра, ~30 ГБ RAM) хватает с запасом.
Основное время — 34 обучения LightGBM (2 фолда × M0, 4 ablations, 3 clean-history,
8 propensity-вариантов) и бутстрэп.

## Что происходит при запуске

1. **Самопроверки** на синтетических данных (≈5 с): взвешенный PR-AUC против `sklearn`,
   эпизодная метрика против исходной `episode_metrics`, причинность propensity. Если что-то не
   прошло — прогон останавливается до чтения панели.
2. **Preflight**: версия схемы `2.0`, SHA-256 файла, число строк, `date_min`/`date_max`,
   обязательные поля и точные границы цели, отсутствие 2026 года, отсутствие сырых
   идентификаторов. Любое несовпадение → `status: "contract_failed"`.
3. **Загрузка**: только размеченные строки с `d_target_end_date_exclusive <= 2025-01-01`.
   Строки 2025 года в память не попадают; они участвуют лишь в агрегатных проверках контракта.
4. **Эксперименты** по двум фолдам, бутстрэп, gates, stress 2021. Для propensity H1 делится по времени:
   первая половина — подбор `m`, вторая — Platt и порог (та же схема, что в 08/09).
5. Если M0 не воспроизводится → `status: "m0_reproduction_failed"`, остальные эксперименты не
   выполняются, заявлений об улучшении нет.

## Где результаты

В `/kaggle/working` (панель **Output** справа):

- `research_results_pre2025.json` — все агрегаты, CI, gates, решения по гипотезам;
- `research_summary_ru.md` — сводка для команды (та же, что показывается в конце notebook);
- `results_weather_pre2025.json`, `summary_weather_ru.md` — раздел 9 (погода).

Погода Москвы (Open-Meteo, реанализ ERA5, CC BY 4.0, 2019–2025) встроена в notebook как gzip+base64;
при загрузке проверяется SHA-256 `e190eb69…a97e`. Интернет не нужен. Раздел 9 проверяет, что M0 совпадает
с FULL-прогоном 05 (PR-AUC 0,5448 / 0,6161, допуск 0,002).

Построчные прогнозы, модели и идентификаторы каналов/объектов **не сохраняются**. Перед записью
JSON проверяется на отсутствие ключей `d_channel_key`/`d_object_key`.

## Что вернуть команде

1. `research_results_pre2025.json`
2. `research_summary_ru.md`
3. `results_weather_pre2025.json` и `summary_weather_ru.md` (если включён раздел 9)
4. Строку статуса из вывода notebook (`completed` / `contract_failed` / `m0_reproduction_failed`).

Если прогон был в `SMOKE`, так и написать: эти числа не сравнимы ни с чем.

## Частые проблемы

| сообщение | что делать |
| --- | --- |
| «Ожидался ровно один panel_manifest_v2.json, найдено: 0» | не подключён dataset через Add Input |
| «… найдено: 2» | подключены две версии панели; оставить одну |
| «SHA-256 файла панели не совпал с манифестом» | dataset повреждён или подменён файл; перезалить версию |
| «Число строк не совпало с манифестом» | то же |
| Kernel died / Out of memory | проверить, что выбран CPU-ноутбук, а не маленький инстанс; закрыть другие сессии |
| `m0_reproduction_failed` | прислать JSON целиком: в `m0_reproduction_diagnostics` будет причина |
