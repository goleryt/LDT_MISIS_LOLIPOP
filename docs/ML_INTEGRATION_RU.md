# ML-пакет LCT_ML_backend_v1 в backend

## Как это устроено

Расчёт идёт **раз в сутки отдельной задачей**, API модель не запускает:

```
events_journal ──► app/ml_job.py ──► MLRuntime.score_day ──► ml_scores ──► API / интерфейс
 (последние 430 суток)   (экспорт CSV по годам)   (бандлы)      └─► predictions (top-25, cooldown 3 суток)
```

- `backend/app/ml_runtime/lct_ml_runtime.py` — точка входа ML-команды, без изменений.
- `backend/app/ml_job.py` — экспорт журнала и справочника каналов, вызов runtime, сохранение, отбор оповещений.
- `ml_scores` — ответ runtime как есть (модель, окно, `decision_status`, `reason_codes`, `maintenance_context`, полный payload).
- `predictions` — только отобранные top-K по газу; вкладка «Прогнозы» и решения диспетчера — прежние.
- `GET /api/v1/objects/{id}/sensors` отдаёт последний сохранённый результат по каналу (`risk_*`).
- Никаких заявок и уведомлений по shadow-оценке не создаётся (правило пакета).

## Запуск

Нужно окружение задачи (Python 3.11–3.12): `pip install -r backend/requirements-ml.txt`.
API-процессу эти пакеты не нужны.

```bash
cd backend
python -m scripts.run_ml_daily                 # за последние закрытые сутки
python -m scripts.run_ml_daily --date 2026-06-20
```

Повторный запуск за тот же день заменяет результат этого дня. Ставить в расписание раз в сутки после закрытия суток.
Нужна история журнала не меньше 401 суток до D, иначе газовый bundle честно откажется (`INSUFFICIENT_HISTORY`).

## Что означает оценка

Газовая модель оценивает **наблюдаемое в журнале пересечение газом 1 % CH4 снизу вверх в сутки D+2**.
Это не вероятность пожара и не подтверждённый инцидент (`operational_ready = false`, режим shadow).
Заметная часть качества — предсказание поверок газоанализаторов: такие каналы помечены
`maintenance_context = possible_recent_silence`, оценка и тревога при этом не скрываются.

Модуль инцидентов (пожар / подтопление / НСД) обучен на заглушке реестра (`label_source = stub`):
записи сохраняются в `ml_scores` (`kind = incident`), но **в интерфейсе пока не показываются**. Показывать их
можно только с плашкой «ДЕМО: модель обучена на заглушке реестра».

## Замена модели

Положить новый `*_bundle.zip` и `.sha256` в `models/bundles/`, переключить `ACTIVE.json`, перезапустить задачу.
Код backend не меняется (см. README пакета, п. 5).
